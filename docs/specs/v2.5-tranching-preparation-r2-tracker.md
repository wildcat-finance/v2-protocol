## Decision register

Confirmed requirements are C-01–C-09 in the spec. In particular, default is a
marker for every newly deployed market, not a closure transition; accepted
withdrawals remain collectible without another eligibility veto.

| Proposal                                                         | State at documentation checkpoint                                                           |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| P-01: 90-day run, observed cure and inclusive cutoff             | Proposed; equality must be consistent with the repayment deadline.                          |
| P-02: inclusive deadline and exact recognized funding            | Proposed; no required close action, with direct-transfer recognition consequence explicit.  |
| P-03: universal dated deposit/borrow rejection and queue opening | Proposed; normal batches/sanctions remain and C-06 collection rights are already confirmed. |
| P-04: zero period, immutability, maturity relation and limits    | Proposed; distinguish zero from disabled and finalize network caps before release.          |

Engineering recommendations (marker timestamp, execution-dispatch retirement,
minimal events, registered-template limit authority and penalty helper design)
must be made concrete in R2-01/R2-02. They are not existing source behavior.

## Evidence already available

- Hook refactor M1–M5 completed at the baseline. The external M5 handoff retains
  the updated hook spec and qualified evidence. Its 749 reported tests in each
  final configuration do not qualify P-01.
- Existing stored-initcode margins: standard 1,597 bytes, revolving 932 bytes;
  open/fixed/periodic hooks 6,196 / 4,834 / 1,899 bytes. Cached deploy artifacts
  only; new feature size/gas remains unmeasured.
- Market sources still have no repayment terms or permanent default marker.
  Both APR execution paths already pass effective values to `_checkAprChange`.
- Existing queue and execution callbacks are separate. Execution defaults to no
  extra restriction in production templates but the core can dispatch a vetoing
  callback, which does not enforce the newly selected collection guarantee.
- Creation parameters and hook calldata have fixed assembly layouts. Keep the
  documented layout map and generated interfaces synchronized.

## Resume and checkpoint protocol

After maintenance, read the spec and this tracker, check the branch/tree, and
start R2-01. Do not restart the completed hook refactor or infer approval of
every other-session proposal from the request to commit this draft.

At each task checkpoint, record the actual commit, changed behavior, tests,
size and remaining limitations here. Stage Solidity for user review, then use
signed kethcode commits after approval. The user pushes. Keep all supplied
reference PDFs, the lifecycle sketch and the voice guide outside commits.

The documentation checkpoint contains only Markdown. Link and whitespace checks
are required before its commit; a runtime suite rerun is not required. Its
signed commit and maintenance receipt are saved outside the repository so this
file does not need a self-referential commit hash.
