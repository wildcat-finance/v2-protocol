## Decision register

Confirmed requirements are C-01–C-09 in the spec. In particular, default is a
marker for every newly deployed market, not a closure transition; accepted
withdrawals remain collectible without another eligibility veto.

| Proposal                                                      | State at documentation checkpoint                                                                                                                                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P-01: 90-day run, observed cure and inclusive cutoff          | Selected 2026-09-25. Full cure at the cutoff counts, including a later transaction in the same block; latch an uncured default only afterward.                                                         |

### Size priority and limits

The user directed functionality first, then a separate bytecode-reduction pass.
The measurements used the existing Solidity 0.8.25 / viaIR / optimizer-runs-44
configuration throughout. The first straightforward build was too large;
preventing compiler specialization removed duplicate transition bodies but did
not close the gap. An external-calculator experiment was archived and removed
from the active source. No external accounting dependency is selected.

Runtime and stored-initcode size remain release blockers. Functional runs may
use a larger test-only code-size allowance (the existing large test contracts
need it too). They exercise the actual factory paths, but do not prove network
deployability. Keep the separate artifact-size check and record its failure;
do not drop features to turn that check green. The plan now reflects this
ordering instead of its original prototype-size gate.
