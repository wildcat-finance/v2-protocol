### Readthrough: reuse existing techniques first

These are candidates, with no claimed byte savings until individually measured:

1. **Avoid redundant memory allocation.** Optimized market IR contains seven
   discarded struct-zeroing calls, including four in the new state-return
   wrappers. The nested `LifecycleTransition` initializer also allocates objects
   that are replaced immediately; accrual records are allocated twice. Extend
   the existing [pointer-return technique](../../src/libraries/FunctionTypeCasts.sol),
   and consider one explicitly initialized workspace with reusable record slots.
2. **Share withdrawal-payment arithmetic.** Both payment functions in
   [WildcatMarketBase](../../src/market/WildcatMarketBase.sol) remain separate in
   optimized IR. Share the calculation and return deltas for the event-emitting
   path. Preserve exact floor rounding, zero-payment behavior and event order.
3. **Use the existing event/error encoders.** New lifecycle events/errors use
   ordinary Solidity encoding. [MarketEvents](../../src/libraries/MarketEvents.sol)
   and [MarketErrors](../../src/libraries/MarketErrors.sol) provide compact
   precedents. Accrual snapshots already contain the six event words in order;
   logging that buffer could avoid reconstructing it during replay.
4. **Combine safe scalar predicates.** Apply
   [BoolUtils](../../src/libraries/BoolUtils.sol) only where both operands are
   normalized booleans and eager evaluation preserves behavior. Retain essential
   short-circuiting, especially around external calls and potentially reverting
   expressions.
5. **Tighten internal terms/getter handling.** Compare one internal decoder and
   compact external wrappers. A terminal assembly `return` must not be copied
   into a public getter that is called internally. Keep callback-safe reads and
   the constructor-proved timestamp bounds.
6. **Review temporary integer widths.** Narrow fields occupy whole memory words
   and add masks/counter checks. Measure wider internal snapshot/counter fields;
   preserve packed lifecycle storage, `MarketState`, hook ABI and checked
   accounting bounds.
7. **Reduce hook setup/query overhead.** Creation constructs the same constraint
   tuple twice. Try one shared snapshot without weakening override/discovery
   behavior. Periodic closure-query encoding is another fixed-buffer candidate,
   with revert, return-length and bool-validation semantics preserved.

The earlier `_runtimeConstant` work is already effective: optimized IR has one
transition body and one batch-commit body per market. The now-unused
`_processExpiredWithdrawalBatch` is already absent from optimized IR, so deleting
it would clean up source without saving deployed bytes. Factory-only reductions
also do not shrink the separately stored market creation code.

Start with allocation and arithmetic sharing, then the smaller encoding and
predicate candidates. Measure at canonical runs 44 and retain focused behavior,
ABI/storage and gas evidence. External calculators or deployment-storage changes
remain later options; no architectural change is selected by this readthrough.
The full report and IR evidence are preserved outside the repository.
