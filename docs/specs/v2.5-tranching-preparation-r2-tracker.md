## Decision register

Confirmed requirements are C-01–C-09 in the spec. In particular, default is a
marker for every newly deployed market, not a closure transition; accepted
withdrawals remain collectible without another eligibility veto.

| Proposal                                                      | State at documentation checkpoint                                                                                                                                                                      |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P-01: 90-day run, observed cure and inclusive cutoff          | Selected 2026-09-25. Full cure at the cutoff counts, including a later transaction in the same block; latch an uncured default only afterward.                                                         |
| P-02: repayment completion and deadline test                  | Authorized working assumption: automatic funded closure. Prototype the existing full-funding criterion; preserve inclusive cutoff and historical default, with distinct donation/repayment accounting. |
| P-03: dated action gates and their duration                   | Selected: core deposit/borrow rejection and queue-hook bypass on every dated market; batching and sanctions preserved, followed by automatic funded closure.                                           |
| P-04: zero period, immutability, maturity relation and limits | Settled. Zero-day periods allowed with frontend warning; optional immutable terms, 90-day cap and fixed-maturity relation. Final network caps remain R5 work.                                          |

R2-01 selects the timestamp marker, retirement of execution dispatch, reserved
bit 93, effective-config rejection in the constructor, and the three minimal
events in the spec. Creation/getter selectors and the initial packed storage
layout are recorded there. Shared constraint discovery appends two repayment
bounds. Penalty/accounting mechanics and bounded closure must now be proved
in the R2-02 prototype. These are implementation choices, not existing behavior.
