review of Wildcat V2.5. It is not a deployment attestation, a mainnet ceremony
plan, or evidence that the review is complete.

## Source review boundary

Review every first-party file under `src/`, including interfaces, libraries,
stored-initcode helpers, and source for reused singletons. Prioritize these
runtime paths:

| Area | V2.5 runtime role |
| --- | --- |
| Markets and withdrawals | Standard and revolving accrual, borrowing, repayment, delinquency, closure, scaled balances, queues, batches, and reserves |
| Origination and identity | Standard and revolving factories, CREATE2 salts, transient constructor parameters, registry writes, borrower principals, and transfers |
| Hooks and role providers | Open, fixed, and periodic terms; hook administration; credentials; provider factories; access lists; pull, push, and cached authorization; exact canonical-wrapper admission |
| Wrappers, sanctions, and SphereX | Generation routing, pooled custody, rounding, recipient policy, escrow migration, sanctions callbacks, engine selection, and registered senders |
| Lenses, interfaces, and shared code | Enumeration, aggregation, cross-generation live reads, event semantics, math, casting, and bounded iteration |

Tests, docs, mocks, scripts, schemas, and deployment UI are supporting review
evidence, not part of the contract source boundary. A security review of the
deployment system or ceremony is a separate operational scope.

Third-party code under `lib/` is outside the first-party source boundary, but
dependency assumptions and Wildcat's use of those libraries remain in scope.

## Deployment boundary

The audit source freeze is not a deployment attestation and must not be
described as the currently deployed V2.5 runtime.

- Mainnet production comparison source is V2.1 at `c7be403`.
- The latest V2.5 Sepolia production source recorded by the repository is
  `49f891c`; its live ceremony source is `60b1a1a`.
- The previous
  [14-item Sepolia inventory](../../deployments/sepolia/inventory-pending-v2-5-sepolia-fix-1/)
  is historical planning and testnet evidence, not an approved mainnet scope.
- Exact deployed addresses, generations, code hashes, lifecycle state, and
  receipts belong to [`deployments/`](../../deployments/). Predicted addresses
  and plans are not deployment evidence.

The intended mainnet runtime set and every reused singleton must be pinned
separately before release. Source changes to reused ArchController, sanctions,
SphereX, or legacy-wrapper components do not by themselves imply that new
instances will be deployed.

The role-provider implementations are all source-review scope even if only a
subset is selected for the initial ceremony. Adding a provider or approving a
borrower-account factory changes the deployed trust boundary and requires an
explicit ceremony decision.

## Trust and authority

| Actor or dependency | Authority or assumption |
| --- | --- |
| Borrower | Credit risk; may draw assets and use only the configuration powers granted by market and hook terms |
| Lender or arbitrary caller | Untrusted; permissionless entrypoints must not grant discretionary borrower, hook, provider, registry, or recipient authority |
| ArchController owner | Admits factories and controllers and maintains registry policy |
| SphereX admin, operator, and engine | Select and operate transaction checking and registered-sender state |
| Factory or template fee authority | Selects templates and terms for new markets and can push permitted fee-rate changes |
| Hook administrator | Controls mutable hook policy, separately from market borrower and provider administration |
| Provider administrator or provider | Controls credentials and capabilities assigned by the hook configuration |
| Fee recipient | Receives immutable-market-recipient protocol fees after collection |
| Underlying token | Must provide stable supported ERC-20 transfer and metadata behavior |
| Sanctions sentinel and external list | External liveness and classification dependency for sanctions-gated paths |
| Hook, provider, and token callbacks | Potentially adversarial external calls; market, factory, hook, and wrapper reentrancy boundaries must hold |
| Legacy wrapper factory | Trusted generation-routing dependency for markets that do not declare V2.5 floor rounding |

A market permanently trusts its selected hook address, callback flags,
underlying asset, sanctions sentinel, and immutable fee recipient. Listed
assets and external sanctions dependencies must satisfy
[security assumptions](../security/assumptions.md).

State refresh, bounded withdrawal processing, wrapper creation, and execution
of a ready periodic APR reduction are permissionless. Permissionless execution
does not include choosing terms or recipients outside already committed state.

The audit scope includes dormant borrower-account source, but the initial
ceremony must not approve a borrower-account factory without explicitly adding
its runtime authority to the release boundary. See
[known limitations](../security/known-issues.md#dormant-borrower-account-factory-surface).

## Core security properties

The review should independently test these properties rather than treating the
existing suite as proof:

| Domain | Required properties |
| --- | --- |
| Accounting and delinquency | Scaled supply, balances, pending withdrawals, reserved assets, principal, and fee liabilities remain conserved through accrual, donation, repayment, delinquency, expiry, closure, and rounding. Revolving commitment and base APR apply to the intended supply and drawn portions. |
| Withdrawals and time bounds | Batches settle FIFO, never reserve or pay more than attributable underlying, remain executable after closure when funded, and cannot truncate or wrap timestamps, expiries, durations, or scaled amounts. Full-path growth has a bounded operational route. |
| Origination and authority | CREATE2 salts, transient constructor parameters, predicted addresses, borrower identity, registry writes, hook instances, and SphereX configuration cannot be spliced across callers or callbacks. A revert rolls back market, factory, hook, provider, and registry effects. |
| Hooks, providers, and transfers | Every mutable path has the documented administrator, provider, caller, target set, cache behavior, and callback flags. Canonical-wrapper admission is exact, nonzero, market-specific, and recipient-only; it cannot bypass disabled transfers, authorize noncanonical wrappers, or relax policy for market tokens leaving the wrapper. Borrower transfer changes only intended operational identity and cannot transfer hook administration, provider authority, historical debt, or recipient permissions. |
| Wrappers, sanctions, and reads | Deposits, mints, withdrawals, redemptions, sanctions escrow migrations, and generation routing cannot create unbacked shares, widen the registered-wrapper exception, evade the applicable market-token recipient policy, or consume backing owed to holders. Lens pagination and aggregation must not misidentify generations or silently corrupt actionable state. |

Accepted behavior and representation limits are collected in
[known limitations and accepted behavior](../security/known-issues.md). A path
that exceeds those stated effects remains in scope.

## Verification

Run from a clean recursive checkout of the audit source with Foundry `1.7.1`:

```sh
git submodule update --init --recursive
FOUNDRY_PROFILE=default forge build --force src
FOUNDRY_PROFILE=default forge test --summary
FOUNDRY_PROFILE=default yarn test:fixed --summary
FOUNDRY_PROFILE=deploy forge test --summary
FOUNDRY_PROFILE=deploy forge build --force --sizes src
yarn lint:check
yarn inventory:contracts --release v2.5 \
  --ref 7fad3deffb2f4cb185c466bd539f9bc200d19bc7 \
  --artifacts out --output docs/releases/inventory/v2.5.json --check
git diff --check
```

`yarn test:fixed` pins block timestamp `1724284800` and fuzz seed `0x5eed`.
Foundry runs 1,000 cases per fuzz test and 2,000 invariant runs at depth 30.

During preparation of the previous `1af2fcc` freeze, the forced default build
succeeded and the default suite passed 697 tests across 46 suites with zero
failures or skips. Nine invariant suites each completed 2,000 runs at depth 30
with zero handler reverts. After the `7fad3de` refreeze, the forced default
source build succeeded; all 132 tests under `test/access/` and all 15 tests in
`Wildcat4626WrapperIntegration.t.sol` passed. This is focused preliminary
evidence; the dated verification receipt must record every final gate above
against the exact freeze.

The repository has an intentional formatting baseline. Do not silently run
`forge fmt` or format unrelated source to make `yarn lint:check` green. Record
the exact current failure and its reviewed disposition.

Foundry can print a non-fatal post-compile `unresolved symbol locals`
diagnostic for the SphereX modifier at
`src/spherex/SphereXProtectedRegisteredBase.sol:149`. Compilation and tests may
still exit successfully. Treat any nonzero command status as a failure.

The final handoff must add a dated verification receipt. For each command,
record the exact commit, tool version, exit status, suite and test counts where
applicable, and a digest of retained output. A command list is not evidence
that the freeze passed.

Historical Fizz or Medusa summaries are not reproducible evidence: the
corresponding raw artifacts and harness state are not retained in the current
repository. Reconstruct and rerun them against the freeze before citing them.

change `src/` without declaring a new freeze and review delta. The audit freeze
