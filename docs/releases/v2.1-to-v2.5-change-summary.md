# V2.1 to V2.5 source changes

Prepared 2026-10-05 for the [V2.5 audit quote](./v2.5-audit-quote.md).

V2.5 retains the V2.1 credit-market model and substantial implementation code.
`WildcatArchController`, the SphereX sources, sanctions escrow, and several
shared libraries have unchanged declarations after presentation normalization.
The market, hook, factory, wrapper, and lens changes are substantial: their
retained code now participates in different accounting and authority flows.
The full 10,498 nSLOC is the review scope, not a count of newly written logic.

## Size and retained code

V2.1 contains 62 source files and 6,391 nSLOC under the same counting method.
All 62 paths remain in the V2.5 package. The following groups partition the
current 100 files; line counts are their current V2.5 sizes.

| Source classification | Files | V2.5 nSLOC |
| --- | ---: | ---: |
| Declarations unchanged after normalization | 23 | 1,137 |
| Only an assembly `memory-safe` annotation added | 1 | 106 |
| Existing files with substantive or structural changes, including retained code | 38 | 6,387 |
| New paths, including extracted and copied code | 38 | 2,868 |
| Total review scope | 100 | 10,498 |

The first group ignores comments, formatting, function/declaration ordering,
and equivalent elementary type spellings. Its imports are unchanged. Its
Solidity pragmas were narrowed to `0.8.25`; both snapshots already select that
compiler in `foundry.toml`. The annotation-only file is `SafeCastLib.sol`.
An optimizer promise is recorded separately from presentation changes.

At function level, 342 of V2.1's 588 explicit definitions with bodies remain
identical at their original path and declaration identity after normalization.
Another 25 current definitions exactly match a V2.1 definition at a different
location. These counts include constructors, modifiers, and empty implementations;
they exclude abstract declarations and inherited-only functions. The current
scope has 999 such definitions. Copies can share a predecessor, so the 25 are
not necessarily 25 distinct old functions.

Neither these counts nor the 4,107 nSLOC net growth measures changed logic or
audit effort. Getters and accounting routines count equally as functions;
new files contain old logic; changed files contain unchanged functions. The
line-count tool also remains sensitive to source layout. Reused code needs
review in its new calling, storage, and dependency context.

## Components with narrow changes

`WildcatArchController.sol` supports the expected reuse claim. All 36 explicit
function/modifier definitions match, including bodies and headers. Inheritance,
state declarations, and imports match; the complete compiled ABI and
compiler-visible storage layout match. Its changed `MathUtils` dependency is
used only for `min`, whose implementation is unchanged. The relevant external

## Changes requiring substantive review

The table separates continuing design from the changes inside it. File and
function identities in the comparison record provide the detailed source map;
the [release notes](./v2.5.md) link to the behavioral specifications.

| Area | Retained foundation and material changes |
| --- | --- |
| Standard markets and accounting | Retains scaled lender balances, interest accrual, reserves, and FIFO withdrawal batches. Amounts entering scaled accounting now round down. Payment and release remainders carry fractional value across settlement, contribute to debt/reserves, and require revised capacity checks. View and mutating paths share a transition engine instead of separately implementing the old state calculations. `MarketState` and `WithdrawalBatch` grow; batch representation widens while admission remains capped. |
| Repayment and default | Adds immutable repayment terms, chronological processing of repayment boundaries, and historical funding checkpoints. From the repayment date, deposits/borrowing stop, reserves become 100%, and queuing bypasses hook restrictions. Full funding triggers automatic closure; surplus recovery is separate. Permanent default records cover prolonged penalty and missed repayment deadlines. Delinquency tracking now advances even at zero penalty APR. These changes reach ordinary state-update, repayment, withdrawal, and view paths. |
| Revolving markets | Adds `WildcatMarketRevolving` and its factory over the shared market implementation. Drawn principal is tracked separately; interest combines commitment-fee accrual with utilization-weighted borrower APR. Explicit repayments reduce principal after nonprincipal debt, while donations add liquidity without being treated as principal repayment. Shared base changes therefore affect both market families. |
| Hooks and term policies | Open/fixed behavior moves into `BaseHooks` and separate policies, with extension points for policies composed into new implementations. This extraction also changes behavior: repayment parameter freezes, canonical-wrapper recipient admission, revised credential checks, and rounding in temporary reserve requirements. Adds periodic withdrawal windows and announced APR reductions. Withdrawal collection no longer invokes `onExecuteWithdrawal`, and new markets reject configurations enabling it. |
| Borrower and administrator authority | Adds the identity registry and separates market borrower, registered principal, hook administrator, and provider administrator. Includes two-step transfers and factory index updates. The old automatic borrower-as-provider setup is removed. Registry account-factory paths are source-scope additions even where activation is deferred. |
| Role providers | The two existing generic provider interfaces remain unchanged. `AccessListRoleProvider`, its factory, and `ManagedRoleProvider` are new scoped implementations, with membership, credential, deterministic-deployment, and administrator-transfer behavior. Excluded provider implementations are not counted here. |
| Factories and creation-code handling | Retains CREATE2, caller-bound salts, transient constructor parameters, registration, and hook-template concepts. Adds repayment/identity/wrapper inputs, creation-code hash commitments, and raw/split/executable storage readers. The revolving factory copies substantial standard-factory code: 15 definitions exactly match V2.1. Origination-fee zero handling, fee propagation, pagination, and event payloads also change. Prepared installation constructors and codec helpers are part of the scope. |
| ERC-4626 wrapper and factory | Retains scaled market-token backing and canonical wrapper lookup. Reworks floor/ceiling conversions, exact transferred-share checks, solvency checks, and limit behavior. Adds generation routing to the legacy factory, atomic wrapper registration, recipient-policy checks, dynamic borrower authority, and sanctioned-share escrow handling. Both wrapper and factory have ABI and declared-storage changes. |
| Lens and shared support | Splits `MarketLens` into a facade and core/aggregation/live helpers using `staticcall`. Adds cross-factory and lifecycle reads, changes nested result tuples, and decodes the exact legacy accounting tuple shape. Cosmetic token metadata becomes bounded and best-effort while accounting reads remain strict. Supporting changes include packed FIFO storage, extended hook calldata layouts, and changed events/errors. These are not merely function moves. |

The standard market family, existing concrete hook templates, standard factory,
and wrappers all have changed compiled ABIs and declared storage layouts. The
lens ABI changes too, despite its unchanged empty compiler storage layout.
Unchanged selectors can also return changed tuples. ABI equality alone does
not establish equivalent implementation, as the sanctions sentinel illustrates.

V2.5 supplies lifecycle and hook extension surfaces for later tranching; the
scope contains no tranche vault, senior/junior shares, waterfall, or tranche
policy. Those remain V2.6 work.

## Method and limits

The source comparison parses both snapshots with `@solidity-parser/parser@0.18.0`.
It preserves inheritance order, storage declarations and initializers, struct
and enum field order, modifiers, parameter names/data locations, function
bodies, and assembly flags. It compares functions independently of their file
order and looks across files for exact matches. Changed routines and their
callers were then inspected to distinguish extraction from behavior changes.
This is a change assessment, not a security audit or a proof of equivalence.

Counts use `solidity-code-metrics@0.0.28`, including interfaces and shared code.
Physical SLoC excludes blank and comment-only lines; normalized SLoC also uses
the tool's function-header collapse. The current totals are 13,103 physical
SLoC and 10,498 nSLOC. Per-file counts and tool versions are retained in the
comparison record.

Both source graphs compiled successfully for ABI, storage layout, and AST
output with Solidity `0.8.25`, resolving dependencies at each snapshot's own
gitlinks. OpenZeppelin, Solady, Solmate, and Forge Std revisions match. ABI
comparison includes outputs, names, events, and errors. Storage comparison
removes compiler-generated AST IDs but preserves type structure, slots, and
offsets. Compiler storage output omits immutables, transient state, and manually
assigned assembly storage; equal layouts are not migration approval.

No V2.1-to-V2.5 bytecode identity is claimed. Build configuration changes include
the default via-IR pipeline, optimizer settings, and metadata settings; source
ordering can also change compiler output. This assessment does not verify a
deployment or extend the source scope of any [prior audit](../../audits/README.md).
The requested audit remains a full review of the quoted package, with this
comparison supplied to help reviewers allocate their time.
