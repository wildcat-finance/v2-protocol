# V2.5

## Source Boundary

V2.5 is the active release line. Its final tag, source commit, and generated
contract inventory will be added after source freeze. This page describes the
delta from [V2.1](./v2.1.md); it does not attest to deployment status.

## Markets and Accounting

- `WildcatMarketRevolving` adds revolving-credit accounting with separate drawn
  principal and commitment-fee accrual.
- Normalized amounts entering scaled accounting now round down. Markets expose
  `version() == "2.5"` and `scaledTransferRounding()` for compatibility checks.
- `queueWithdrawalScaled(uint256)` preserves an exact scaled position for
  wrapper and account-abstraction flows.
- Withdrawal settlement uses floor-priced capacity so a fully funded closed
  market can finish its batches.
- `onExecuteWithdrawal` receives the exact batch expiry being executed.

See [accounting](../protocol/accounting.md),
[scaling](../protocol/scaling-and-rounding.md), and
[withdrawals](../protocol/withdrawals.md).

## Terms, Identity, and Access

- `PeriodicTermHooks` adds recurring withdrawal windows and announced APR
  reductions.
- Market borrower and registered principal are stored separately, with a
  two-step borrower-transfer path. Supported V2.5 origination keeps them equal.
- Hook administration is separate from market borrower and credential-provider
  authority.
- Credential validation rejects future push timestamps, classifies non-pull
  providers defensively, and avoids repeated provider queries.
- Access configurations cannot allow an uncredentialed entry path while gating
  the same holder's withdrawal path.

See [borrower identity](../protocol/borrower-identity.md),
[access control](../integrations/access-control.md), and
[periodic-term hooks](../integrations/periodic-term-hooks.md).

## Wrappers and Read Surfaces

- `Wildcat4626WrapperFactory` becomes a generation-aware facade. It handles
  V2.5 floor-rounding markets locally and forwards compatible earlier markets
  to the V2.1 factory.
- V2.5 markets atomically register their canonical wrapper and prevent the
  wrapper's pooled position from being quarantined at market level.
- `MarketLens` becomes a facade over core, aggregation, and live-data helpers to
  remain within deployment-size limits.
- Lens tuples and factory deployment events add borrower-principal, hook,
  provider, fee, and revolving-market state.
- Consumers must select event and lens ABIs from deployment provenance rather
  than version text or address age.

See [ERC-4626 wrapper](../integrations/erc-4626-wrapper.md) and
[event model](../integrations/events.md).

## Deployment Boundary

V2.5 adds new market factories, stored market initcode, hook-template initcode,
the revolving market family, the wrapper-factory facade, borrower identity
registry, access-list provider factory, and lens facade. Exact deployed
generations and lifecycle state belong to [`deployments/`](../../deployments/).

The release plan reuses the existing `WildcatArchController`,
`WildcatSanctionsSentinel`, and `WildcatSanctionsEscrow`; it does not deploy new
compilations of those files. The active branch still carries compiler, comment,
and sanctions-query implementation maintenance in singleton source. Auditors
must therefore distinguish the repository diff from the runtime deployment
scope.

Source ancestry alone does not show which new factories, templates, providers,
or helpers are live.

## Compatibility

Pre-V2.5 markets retain half-up scaled conversion and do not expose the new
scaled-withdrawal or borrower-transfer interfaces. Existing hook instances also
retain the code and configuration with which they were deployed.

Integrations spanning generations must resolve the market factory, hook
template, wrapper factory, rounding marker, event ABI, and lens ABI from the
recorded deployment generation.
